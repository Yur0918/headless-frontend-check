为什么要有这个工具 改前端时「看着对了」不等于能用：DOM 是否真的挂上、点击有没有响应、窄屏会不会横向溢出、 控制台有没有报错、截图有没有截到 —— 这些在浏览器里打开看一眼是查不出来的，只有断言能给出确定答案。

覆盖的场景 不是截图工具

  • DOM 断言——元素存在、数量、属性状态，逐条给期望值
  • 下载校验——生成的文件真的能下、字节数与格式头对得上
  • 交互回归——点、填、搜，走真实事件链而非直接改状态
  • 控制台与请求——抓 error 级日志与失败请求

输出原则 可复现

  • 断言失败时报期望值与实际值，不只说「不通过」
  • 截图按视口命名，可直接进 PR 作为改动证据
  • 退出码非零，可直接挂进 CI 卡住回归
  • 无需改项目配置，零侵入接入
